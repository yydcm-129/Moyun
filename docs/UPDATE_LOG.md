## v0.0.0～v0.0.3：基线阶段

当前仓库的 Git 历史中，这四个版本分支均指向 `995fe90`，没有可单独归属的版本提交。因此不能从仓库证据中声称这四个版本存在不同功能；后续接手者应将 `995fe90` 视为共同基线。

## v0.0.4：写作工作流改进

提交：`5b4ff0d feat: release v0.0.4 writing workflow improvements`

- 修复影响文件上传和静态网页的历史致命问题，并重新构建静态入口。
- 完善字数检测：AI 内容不足时支持二轮补写，补写期间继续累计计时、总字数和每秒字数；流式请求优先。
- 强化角色设定、资料条目、大纲等上下文的识别和注入；反向生成细纲时读取大纲、角色与相关设定。
- 创作设定工作台增加 AI 补充能力；资料条目支持自定义类型和别名/类似词调用。
- 生图设置增加图片数量、检测逻辑及画师串更新能力；未修改用户提供的示例文件。
- 增加并完善卷纲硬性边界、细纲分层、超时保护和全局流式策略。
- 增加角色当前状态与事件时间线的自动记录/辅助记忆逻辑。
- 移动端续写框全选删除后恢复焦点，操作入口逐步统一为标准按钮。

## v0.0.5：卷纲与上下文工作流增强

提交：`967e9bf feat: improve volume outline and context workflow`

- 卷纲成为大纲的默认/必选层级，支持卷标题、章节范围、摘要编辑及放大编辑。
- 卷纲列表设置内部滚动和“收起全部/展开全部”，并把卷纲约束注入正文与细纲提示词。
- 细纲生成强制读取最新大纲；正文存在时按正文与事件时间线优先生成后续细纲。
- 二轮补写结束后直接输出，不再因仍未达标而进入警告死循环，也不再追加“（未完）”。
- 二轮补写继续累计计时、正文总字数和每秒字数。
- 角色、事件时间线、大纲、资料条目增加 AI 补充入口，并支持流式预览。
- 完成若干静态合同检查、JavaScript 语法检查和构建检查。

## v0.0.7：卷纲单项展开修复

提交：`0ae8d44 fix: allow individual volume expansion after collapse all`

点击“收起全部”后，单独点击某一卷的“展开”按钮没有效果，用户无法查看或编辑该卷。

## v0.0.9：卷纲识别、防空白补全与摘要/时间链路修复

分支：`temp/v0.0.8-v009-work`（基于 v0.0.8 稳定副本 `c6f69f4`）。本轮按用户 7 项需求逐项修改，全部改动集中在 `source/moyun.single.html`，构建后同步生成产物。

### ① 大纲工作台的卷纲AI识别

- `buildStructuredOutlineInstruction` 把【卷纲更新】改为必选小节，固定逐卷一行格式 `第N卷｜卷名：XXX｜章节 X-Y｜框架摘要：XXX`，无改动也照抄当前值；卷数与章节边界必须与【现有卷纲】一致。
- `generateOutline` 在【现有卷纲】后注入【卷纲输出要求】，要求大纲文本最前面输出该小节；`aiSupplementOutline` 同样约束补齐空白结构。
- `applyAiVolumeUpdates` 重构为先收集再回填：按行解析卷号/卷名/章节范围/框架摘要，超出既有卷数的行被忽略（卷数量不交给模型扩容）；大纲请求统一 `preferStream: true`。
- “AI修改大纲”复用同一提示词链路，修改意见明确涉及卷纲时可更新对应卷。

### ② 卷纲UI：整体收起

- 新增 `novelVolumesBoardMinimized` 状态与 `toggleNovelVolumesBoardMinimized`，卷纲板头部新增“整体收起”按钮。
- 收起后整块卷纲板替换为一条摘要行（“卷纲已整体收起 · N 卷”+逐卷范围），点击“展开卷纲”或摘要行即可恢复；放大编辑快捷行在收起时隐藏。
- 与既有“收起全部/展开全部”互不干扰：整体收起更深一层，单项展开逻辑保持 v0.0.7 行为。

### ③ AI补全不留空白

- `aiSupplementStoryBible`：project 五字段和 worldView 必填，禁留空/禁写“无/暂无/待定”，素材不足须合理推断并标注“（据现有信息推断）”；entries 至少 3 条。保存后仍有空字段时宿主兜底写入占位说明，工作台不再出现“AI已补充却一片空白”。
- `aiSupplementSelectedCharacter`：8 个档案字段全部必填，currentState ≤60字、其余 30-120 字。
- `aiSupplementStoryBibleEvent`：6 字段全部必填（标题≤20/时间≤24/摘要≤60/因果≤80 字），新增 `EVENT_FIELD_MAX` 常量表并在回填处硬截断。
- `aiSupplementStoryBibleEntry`：name/summary/details 必填并有字数上限。

### ④ 事件时间线自动填充约束

- 时间线头部新增“折叠列表/展开列表”按钮；折叠后仅一条摘要节点（项数+当前选中事件），点击展开。
- 事件标题输入 `maxlength=120`、占位提示“建议 20 字以内”，时间文本 `maxlength=40`；`normalizeStoryBibleEvent` 保存层再截标题 120 字。
- AI 事件补充提示词按 ③ 的字段上限约束输出，避免超长标题挤爆阅读区。

### ⑤ 关系图“当前态”字数硬限制

- `normalizeCharacterRelationships` 保存层把 attitude 统一截到 30 字、changeReason 截到 120 字，任何来源（AI、导入、草稿回填）都不会超限。
- 三处输入框（原卡编辑器、角色工作台当前态、草稿审阅）加 `maxlength=30` 与“（30字内）”提示；AI 提示词改为“态度描述(20字以内)”。
- `.moyun-rel-fact-state` 由 `nowrap` 改为自动换行 + `max-width:52%`，弹窗内不再溢出。

### ⑥ 正文摘要分类修复

- 正文生成不再要求模型连带输出读者评论：7 处提示词（主 sysPrompt、续写、修复、白鸟回读、预检、finalCheck、白鸟承载）全部改为“摘要结束后立即停止”，评论仅保留独立的 `generateChapterComments` 调用。
- 摘要提示词统一为 60-100 字；`parseChapter` 保存层新增 120 字硬截断，防模型把书评误灌进摘要。
- `findLastSummaryMarker` 识别范围扩展：`---剧情摘要---` 分隔线、`## 剧情摘要` 标题、`**本章摘要**` 加粗、`【摘要】`、裸“摘要”行和 `Summary` 均可正确切分。

### ⑦ 剧情时间进入AI链路

- `buildChapterMessages` 新增 `storyTimeOutputRule`：前文上下文（已有 `formatSnowwingChapterStoryTimeContext` 注入“剧情时间（独立元数据）”行）中存在上一章剧情时间时，要求模型先读取上一章时间、结合本章正文推进时间，并在标题行前单独一行输出本章时间，格式固定 `【历法或相对时间·时段】` 且须含日期数字或“当日/翌日”锚点，整行 ≤40 字。
- 新书/无时间线时不注入该规则，避免凭空造历法。
- `parseChapter` 既有时间行剥离逻辑负责识别该行，章节保存与重掷路径写入 `storyTime`，编辑模式“剧情时间”字段继续有效。

## 版本与回滚规则

1. 每轮修改前从上一稳定版本创建临时分支。
2. 版本号只提升最后一位，例如 `v0.0.7 → v0.0.8`。
3. 修改源码优先于生成产物；运行 `npm run build` 同步 `index.html`、`assets/css/moyun.css` 和 `assets/js/moyun.js`。
4. 完成构建、语法、差异和必要的浏览器/响应式测试后，才可将临时分支作为新稳定版本。
5. 回滚时优先切换到对应版本分支或提交，不使用破坏性重置覆盖用户数据。
