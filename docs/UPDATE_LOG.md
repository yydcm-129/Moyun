## v0.0.0～v0.0.3：基线阶段

当前仓库的 Git 历史中，这四个版本分支均指向 `995fe90`，没有可单独归属的版本提交。因此不能从仓库证据中声称这四个版本存在不同功能；后续接手者应将 `995fe90` 视为共同基线。

## v0.0.4：写作工作流改进

提交：`5b4ff0d feat: release v0.0.4 writing workflow improvements`

- 修复影响文件上传和静态网页的历史致命问题，并重新构建静态入口。
- 完善字数检测：AI 内容不足时支持二轮补写，补写期间继续累计计时、总字数和每秒字数；流式请求优先。
- 强化角色设定、资料条目、大纲等上下文的识别和注入；反向生成细纲时读取大纲、角色与相关设定。
- 创作设定工作台增加 AI 补充能力；资料条目支持自定义类型和别名/类似词调用。
- 生图设置增加图片数量、检测逻辑及画师串更新能力；未修改用户提供的示例文件。
- 增加并完善卷纲硬性边界、细纲分层、超时保护和全局流式策略。
- 增加角色当前状态与事件时间线的自动记录/辅助记忆逻辑。
- 移动端续写框全选删除后恢复焦点，操作入口逐步统一为标准按钮。

## v0.0.5：卷纲与上下文工作流增强

提交：`967e9bf feat: improve volume outline and context workflow`

- 卷纲成为大纲的默认/必选层级，支持卷标题、章节范围、摘要编辑及放大编辑。
- 卷纲列表设置内部滚动和“收起全部/展开全部”，并把卷纲约束注入正文与细纲提示词。
- 细纲生成强制读取最新大纲；正文存在时按正文与事件时间线优先生成后续细纲。
- 二轮补写结束后直接输出，不再因仍未达标而进入警告死循环，也不再追加“（未完）”。
- 二轮补写继续累计计时、正文总字数和每秒字数。
- 角色、事件时间线、大纲、资料条目增加 AI 补充入口，并支持流式预览。
- 完成若干静态合同检查、JavaScript 语法检查和构建检查。

## v0.0.6：工作台补充与悬浮球移除

提交：`e120598 feat: 完善卷纲与工作台补充并移除进度悬浮球`

## v0.0.7：卷纲单项展开修复

提交：`0ae8d44 fix: allow individual volume expansion after collapse all`

### 问题

点击“收起全部”后，单独点击某一卷的“展开”按钮没有效果，用户无法查看或编辑该卷。

### 修复

`toggleNovelVolumeCollapsed` 在全局折叠状态下现在会退出全局折叠，并只保留当前卷为展开状态，其余卷继续折叠。卷纲内部滚动逻辑保持不变。

## 版本与回滚规则

1. 每轮修改前从上一稳定版本创建临时分支。
2. 版本号只提升最后一位，例如 `v0.0.7 → v0.0.8`。
3. 修改源码优先于生成产物；运行 `npm run build` 同步 `index.html`、`assets/css/moyun.css` 和 `assets/js/moyun.js`。
4. 完成构建、语法、差异和必要的浏览器/响应式测试后，才可将临时分支作为新稳定版本。
5. 回滚时优先切换到对应版本分支或提交，不使用破坏性重置覆盖用户数据。
