## 已落实的行为

| 计划 | 变化与核对方法 |
| --- | --- |
| 1 预算与摘要 | 原文、摘要、记忆、范围总结及交接共用前文上限；必带资料超限阻止发送。摘要章数和单章上限参与实际请求，保存摘要不再硬截120字。边界包括0、极小预算、只读记忆、省token和禁截断。 |
| 2 检索 | 从原文按句段建子块，3个相邻子块组成父块；父子均可命中，子块按预算补父场景。中文双字词项检索与外部向量以RRF融合，再作本地规则排序，可选外部`/rerank`。不是直接引入Python检索服务。 |
| 3 旧记忆 | 按稳定章节ID保留记录，正文修改后标明待核对；确认保留与重新整理分开，未关联记录可见，不能凭空把205条历史记录猜配回章节。 |
| 4 注入 | 使用明确history槽位，相关事实不再附到最后一条生图或校验消息；按相关度、预算和去重结果发送。界面说明实际发送条数、渠道、命中理由与未发送原因。 |
| 5 存储 | 保留原`NovelWriterV6/kv`与`DB.saveLibrary`入口；目录、公共设置、书、章、记忆、原文块、请求快照分记录，单事务提交。请求快照延后读取，导出和本机恢复点保存前补齐。保留迁移前`library_v6`，未为创作数据新增localStorage键。 |
| 6 分类 | 正派、反派、其他NPC；旧角色默认其他NPC，不按姓名猜阵营，原势力独立保留，可和搜索组合筛选。 |
| 7 批量 | 当前结果全选、跨筛选保留选择；分类、境界/等级、力量等级、身份、状态、标签、势力共用字段配置。保持/设值/清空、标签追加移除、预览、一次保存、失败回滚、最近一次撤销与冲突阻止。等级进入AI角色资料。 |
| 8 卡顿 | 不再为切书复制大请求快照；普通保存只写变化记录；无待保存内容关页不再组装并序列化全库。早期章节编辑草稿与生成中断草稿仍有保护。 |

“保存后续重生成请求快照”默认开，在全局设置的上下文页可搜索。关闭后只影响后续生成，仍可按当前配置重写，旧快照不删。全量备份含这些章节请求，但不含独立本机书籍恢复点，导出选择页和快照页均说明。

## 卡顿的实际原因

输入原有两秒防抖，因此“每次按键都读取整库”不准确。已确认的成本来自真正保存时的整库处理与写入、载书时复制章节内的大请求、关页时重复同步和整库JSON转换。启动还包括Vue模板编译、Tailwind处理、存储读取和渲染，不能把所有等待归给IndexedDB。CPU采样与数据库读写探针均在隔离浏览器运行。

新存储仍扫描章节文本等小记录计算签名；书架其他书的正文仍会读取，旧逐章记忆集中在书级记忆记录。完整备份、首次迁移和首次索引仍需处理较大数据。这轮减少了最大请求快照与未变化向量块的重复成本，没有声称所有整库处理都已消失。

## 召回对照的意义

同一3000字上限、8个固定事实，调用旧版真实函数与当前生产召回函数：旧摘要4/8、关键词6/8、纯向量8/8、混合8/8。旧摘要故意缺失后4个细节，向量使用固定语义one-hot mock。这证明原文补全、融合、排序、预算与请求链路，不证明真实embedding模型的召回率，也不能作为任意百万字长书的质量结论。

## 交付审阅范围

逐处审阅开发模板、生成文件、保存入口、异步补录、最终history注入、角色公共字段与批量提交/回滚，并对照八项计划。重点核对懒请求的保存/删除/导出一致性、单事务目录提交、书籍及分支隔离、迟到结果与取消、付费开关边界。结构审计继续检查模板闭合、v-else配对、角色卡片同级关系、数据库名称、localStorage键、重名及删除符号；没有扩大审计基线或增加新创作数据localStorage键。

旧测试改动仅对应明确变化：摘要预算、history用途标记、原文块索引、旧记忆待核对、懒请求完整性及新设置位置；保留点击、几何、保存失败与内容指纹断言。未新增运行依赖，未接入外部检索框架。实际暂存区逐项复核，`git diff --check`、`git diff --cached --check`及新增明文凭据模式检查通过。

## 失败记录与修正

- 记忆补录保存失败曾先替换记录：改为串行提交，失败恢复对应章/合并组；不还原整个书库。迟到索引核对正文版本，维度变化拒绝混用，手动重建才能替换全部。
- 首轮完整浏览器门禁快照与角色2项失败：前者比较了不同形态的内存/磁盘数据，后者把仅含书ID的目录误判为整库；改为完整磁盘对比和真实章节字段判断，保留全部原断言。
- 后续复查发现召回与近期原文重复，去重后重建并重新验收。一次进行中的门禁主动停止，不计完整通过。
- 新快照开关加入后，搜索词样例目录缺了一项，补足样例；新增生成测试需等待生成状态结束，修正等待时序，没有改生产行为掩盖失败。
- 恢复后的完整门禁发现旧设置位置断言未更新：Gemini测试输入前新增了快照保留开关。更新相邻项预期，并新增断言保留“截断设置→快照保留→Gemini”的顺序；点击、44px尺寸、越界与状态可逆检查均保留。失败运行另存，不当作最终通过。
- 同一轮角色测试进程启动1.3秒后以Windows异常码3221226505退出，没有断言日志，原因未定位；不把它说成已确认的产品故障或忽略它。独立原命令复跑通过（100人预览1.9ms、应用119.9ms、一次保存、刷新及备份导回）。下一轮前30步通过，但最后的性能进程同样在启动1.5秒后以该异常码退出，系统应用日志未提供定位信息；该轮仍判失败。性能原命令单独重跑通过，代码、输入和断言均未改，随后再顺序执行完整31步，不能拼接几次结果冒充整轮通过。
- 某次9样本启动仅改善20.1%，没有达到30%目标；保留失败文件，再紧邻运行相同旧/新样例检查环境波动，最终数值如实列出。不能挑选早先更快结果作为最终源码证据。

临时文件清理有一项环境限制：自动审核阻止删除遗留临时Edge档案及忽略目录中的审阅文本，未改用其他方式强行删除；它们不入库、不参与构建或公测部署。正常完成的专项档案已由原脚本清理。

## 未覆盖与最大不确定性

没有本轮可用的真实200.7MB用户备份，历史205条失联记忆没有在原件上复验；合成60余MB持久化样例不能冒充真实备份。本轮也没有调用真实embedding/rerank/写作服务，没有真机iOS/厂商浏览器、真实断电或操作系统强杀验证。普通关闭与模拟失败通过不等于断电零丢稿保证。

最大的公测缺口是真实长书、实际服务商费用/跨域/返回格式与模型遵守事实的能力。检索拿到正确素材仍不保证写作模型一定遵守；关键词与本地排序也不具备复杂时序推理。应由公测在作者自选的书与API上确认，不能自动把公测内容同步正式站。

角色批量修改更新当前档案，本轮没有增加逐章成长履历。境界或力量等级提升后，重写早期章节仍需作者核对当时状态；不能把当前等级自动视为所有旧章节里的等级。后续若要自动处理这种时间差，需要单独设计可回溯的角色状态。
